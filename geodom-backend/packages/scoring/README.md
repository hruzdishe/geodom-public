# GeoDom — scoring

Самостоятельный Python-пакет для скоринга квартир и районов Красноярска,
сбора исходных данных и расчёта инфраструктурных признаков.
Передавайте бэкендеру **всю эту папку**; её содержимое может быть корнем GitHub-репозитория.

В комплекте только код, настройки, JSON Schema, документация и синтетические тесты.
Объявлений, фотографий, выгрузок OSM, границ районов, экологических наблюдений,
готовых признаков, архивов и секретов здесь нет. Рабочие данные необходимо
подключить отдельно из БД или получить парсерами.

## Быстрый старт

Python 3.12–3.14. Все команды выполняются из этой папки.

```bash
uv sync --locked
uv run python examples/backend_example.py
uv run pytest -q
```

Первая установка требует доступа к пакетному реестру. Пример и тесты работают
без сети и без продуктовых данных. Пример использует только вымышленные записи.
Альтернатива в своём виртуальном окружении: `python -m pip install .`, затем
`python examples/backend_example.py`. Для тестов отдельно установите pytest.
При pip версии выбираются из диапазонов; `uv sync --locked` использует lock-файл.

Начать интеграцию: [BACKEND.md](BACKEND.md).
Получение данных: [PARSERS.md](PARSERS.md).
Формулы: [SCORING_README.md](SCORING_README.md) и
[DISTRICT_SCORING_README.md](DISTRICT_SCORING_README.md).

## Состав

| Путь | Назначение |
|---|---|
| `src/krasnoyarsk_ml/scoring.py` | Скоринг квартир, модели Preferences и ScoringConfig |
| `src/krasnoyarsk_ml/districts.py` | Скоринг районов и проверка файловых снимков |
| `src/krasnoyarsk_ml/features.py` | Расчёт признаков окружения |
| `src/krasnoyarsk_ml/district_geometry.py` | Границы и жилая сетка районов |
| `src/krasnoyarsk_ml/osm.py`, `pipeline.py`, `normalize.py`, `addresses.py` | Парсер OSM, нормализация, адреса |
| `src/krasnoyarsk_ml/housing/` | Парсер Сибдома, фото, экспорт |
| `src/krasnoyarsk_ml/district_environment.py` | Сбор и обработка экологических наблюдений |
| `src/krasnoyarsk_ml/district_export.py` | Генератор экспорта районов и SQL |
| `examples/` | Примеры запросов, схемы и исполняемый пример интеграции |
| `tests/` | Проверки на синтетических данных и подменённых HTTP-ответах |
| `pyproject.toml`, `uv.lock` | Установка и зависимости |

Название Python-пакета `krasnoyarsk_ml`, CLI-команды `ml-*` и переменные `ML_*`
сохранены для совместимости. Название папки — `scoring`.

## Что означает «модель»

Это объяснимые формулы с весами, а не обученные нейросети или CatBoost.
Веса, масштабы расстояний и валидация находятся в Python-коде и ScoringConfig.
Отдельных файлов `.pkl`, `.pt`, `.onnx` нет и для работы они не нужны.

Готового HTTP-сервиса, подключения PostgreSQL/MinIO, геокодера, маршрутизатора
и ипотечного калькулятора нет. Их подключает бэкенд. Тесты проверяют реализацию,
а качество рекомендаций ещё требует пользовательской оценки.

## GitHub

`.gitignore` исключает данные, фотографии, архивы, окружения, кэши и `.env`.
`.env.example` содержит только публичные настройки. Не используйте `git add -f`
для данных. Публикуйте содержимое этой папки, а не весь родительский каталог
с исходным рабочим проектом. Публикация на GitHub в рамках подготовки не выполнялась.

Лицензия на собственный код владельцем проекта не выбрана. Условия источников
и атрибуция OSM сохраняются в метаданных парсеров; публикация кода не означает
автоматическое разрешение на распространение собранных фотографий и данных.
