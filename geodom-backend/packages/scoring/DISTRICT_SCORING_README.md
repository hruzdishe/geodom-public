# Скоринг районов

Реализация: `districts.py`; геометрия: `district_geometry.py`.
Каждый район представлен сеткой жилой территории. Вес точки — площадь
представленного жилого участка `weight_m2`, а не число жителей или объявлений.

Баллы инфраструктуры сначала рассчитываются в жилых точках по формуле квартир,
затем усредняются по площади. Это не балл от среднего расстояния и не среднее
по имеющимся объявлениям. Для компонента возвращаются покрытие, расстояния и
границы оценки. Пропуски не удаляют свой вес. Итог объединяет компоненты
по пользовательским весам, на шкале 0–100.

Фильтры цены и комнат применяются к квартирам для счётчика подходящих предложений,
но не меняют оценку среды района. Отсутствие предложений не означает плохой район.
Для счётчиков нужна полная квартирная выдача после фильтров, а не top-N.

Экология и безопасность не участвуют в баллах. Опциональный `external_evidence`
передаёт справочный контекст, но не превращается в рейтинг. Без отдельного набора
экологических/криминальных данных эти сведения отсутствуют. Формулировки некоторых
предупреждений в исходном коде относятся к прежнему исследовательскому набору;
они не означают, что данные поставляются с этим пакетом.

Версии геометрии, даты снимков и хэши нужно сохранять вместе с признаками.
Готовые границы и сетка в GitHub-комплект не входят; их строит `ml-districts`.
Генератор экспорта `ml-district-export` создаёт отдельную схему `geodom_ml`,
не импортируя квартиры в неизвестную прикладную схему бэкенда.

Вызов из БД или памяти: [BACKEND.md](BACKEND.md).
